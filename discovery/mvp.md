# Гипотезы и объём MVP

## Гипотезы

1. H1. Если дать человеку быстрый общий список того, что уже есть дома
   (без обязательной привязки к месту хранения), то он перестанет покупать
   продукты, которые уже лежат дома, потому что сможет свериться со списком
   прямо перед покупкой — увидим по тому, что участник теста за неделю
   отмечает хотя бы один случай «чуть не купил то, что уже было, но проверил
   в списке».
   finding: duplicate-purchases-confirmed

2. H2. Если сделать структуру мест хранения (кладовка, холодильник,
   морозилка, погреб) такой же простой, как один общий список, а не отдельным
   сложным разделом, то человек без выработанной системы (как в находке про
   Джипера) начнёт пользоваться приложением сразу, без периода привыкания —
   увидим по тому, что новый участник теста добавляет первую запись в
   течение первых двух минут без вопросов и подсказок.
   finding: no-universal-system

3. H3. Если показывать цветовую метку (светофор) по сроку годности прямо на
   карточке продукта, то человек будет использовать продукт до того, как он
   испортится, а не выбрасывать его по инерции, как это происходит с
   заготовками старше нескольких лет — увидим по тому, что за время теста
   доля отметок «использовал» по жёлтому статусу выше, чем доля отметок
   «выбросил» по красному.
   finding: some-preserves-always-get-discarded

4. H4. Если использовать одну и ту же структуру учёта (места хранения плюс
   количество) и для морозилки, и для кладовки или погреба, не делая для
   морозилки отдельный отличающийся экран, то это не помешает пользователям
   с разными типами хранения (как у Дмитрия — несколько морозильников) —
   увидим по тому, что участники с разным набором мест хранения одинаково
   успешно проходят сценарий «добавить, найти, списать» без путаницы.
   finding: same-logic-for-freezer-and-pantry

5. H5. Если снизить порог добавления записи до «название плюс количество»
   без обязательных дополнительных полей, то даже человек, который по словам
   Джипера обычно приходит к системе учёта только с годами и желанием,
   начнёт вести список сразу — увидим по тому, что участник теста продолжает
   добавлять записи на второй неделе использования, а не бросает после
   первого дня.
   finding: setup-ease-conflicting-views

6. H6. Если приложение будет давать ту же полную видимость того, что где
   лежит, которую сейчас дают бумажные способы (стикеры на банках, список на
   двери), то человек, уже довольный своим бумажным способом, всё равно
   попробует цифровой аналог, если он не сложнее в использовании — увидим по
   тому, что участник теста, ранее пользовавшийся бумажным способом, откроет
   приложение повторно на второй неделе, а не вернётся к бумаге.
   finding: manual-methods-feel-sufficient

## Объём MVP

Проверяет верхнюю гипотезу H1.

1. Добавить продукт в список: название и количество, без обязательных
   дополнительных полей
2. Посмотреть общий список всех продуктов, которые сейчас есть дома
3. Найти нужный продукт по названию через поиск — прямо перед походом в
   магазин
4. Отметить продукт как «закончился», чтобы список не расходился с
   реальностью
5. Изменить количество продукта (увеличить при докупке, уменьшить при
   частичном использовании) — без этого список за неделю станет неточным и
   тест потеряет смысл
6. Сгруппировать список по месту хранения (кладовка, холодильник, морозилка) —
   нужно минимально, потому что у одного из подтвердивших находку
   собеседников (Дмитрий) несколько морозильников, и без группировки видимость
   того, что уже есть, перестаёт работать именно для него

Проверка: если убрать любой из шести пунктов, список либо станет неполным
(нельзя добавить или найти), либо быстро разойдётся с реальностью (нельзя
списать или поправить количество), либо перестанет работать для части
подтвердившей находку аудитории (группировка для Дмитрия) — то есть гипотеза
H1 перестанет проверяться. Лишних пунктов не осталось.

## Не входит

- Срок годности и цветовой светофор — проверяет другую гипотезу (H3, про
  порчу продуктов), не H1 про дублирующиеся покупки. Добавление сейчас
  размыло бы тест: непонятно было бы, сработала ли видимость списка или
  сработало напоминание о сроке.
- Семейный доступ и шеринг списка между несколькими людьми — H1
  сформулирована про одного человека, который сверяется со своим списком;
  многопользовательский сценарий (как хотел бы Дмитрий с семьёй) сильно
  усложняет архитектуру ради вопроса, который MVP пока не задаёт.
- Сканирование штрихкодов — ускоряет ввод данных, но не меняет, увидит ли
  человек дубль в списке. Это оптимизация скорости работы, а не тест
  гипотезы.
- Фото продукта — конкуренты (InvenDo, Finly) считают это преимуществом, но
  на проверку H1 фото никак не влияет, только на удобство узнавания.
- Push-уведомления и напоминания — относятся к гипотезе о сроках годности
  (H3), а не к видимости уже имеющегося при выборе покупок (H1).
- Импорт, экспорт, облачный бэкап — инфраструктурная функция для сохранности
  данных, не для проверки того, снижает ли видимость списка число повторных
  покупок.
- Отдельные категории продуктов помимо мест хранения — на старте достаточно
  одной группировки (по месту хранения), чтобы не дублировать структуру
  данных ради гипотезы, которая её не требует.
